# ComHub v2.2.9 Upstream Upgrade Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade the ComHub candidate from the ComHub `v2.2.6` base to upstream LobeHub `v2.2.9` stable while preserving ComHub business customizations.

**Architecture:** Use the existing upstream-sync automation to create the candidate branch, then resolve conflicts by subsystem. Keep upstream's new LobeHub behavior where it does not conflict with ComHub business requirements, and keep ComHub-owned provider, billing, brand, admin, and deployment behavior where the two diverge.

**Tech Stack:** Next.js 16, React 19, TypeScript, pnpm 10.33.0, Vitest, Drizzle/PostgreSQL, GitHub Actions.

## Global Constraints

- Production deployment must remain manual through `.github/workflows/comhub-deploy.yml`.
- Use upstream stable `v2.2.9` for the production candidate; treat `v2.2.10-canary.*` as analysis-only.
- Resolve the merge in a full clone or clean non-partial worktree, not the active partial checkout.
- Preserve ComHub's admin-managed AI provider behavior: backend AI service settings are authoritative in business mode.
- Preserve DB-first model pricing and billing for admin-added NewAPI-compatible models.
- Preserve ComHub brand/admin settings for community CTA text, Skill button text, footer links, sidebar entries, logos, and image upload-backed settings.
- Preserve user setting synchronization semantics: user settings win until an admin explicitly syncs defaults to users.
- Record any newly preserved ComHub customization in `docs/development/comhub-upstream-customizations.md` before merging.
- Do not deploy production as part of this upgrade plan.

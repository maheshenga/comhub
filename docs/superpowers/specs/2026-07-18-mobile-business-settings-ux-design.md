# Mobile Business Settings UX Design

## 背景

当前 Mobile Web 已具备独立入口、移动设置路由和商业设置页响应式外壳。`/settings/plans`、`/settings/credits`、`/settings/billing`、`/settings/usage`、`/settings/referral` 可以在手机宽度下正常打开，桌面侧栏和重复标题已移除，页面也不会产生整体横向溢出。

现状仍主要是桌面内容的纵向缩放：五个页面缺少跨页快捷切换，复杂信息一次性展开，记录仍以表格为主，操作入口分散，套餐横滑缺少明确的滑动行为，加载、空数据和接口失败状态也没有形成统一的移动体验。本设计将目标从“手机可用”提升到“手机上适合高频操作”。

## 目标

- 让用户可以在五个商业设置页之间快速切换，并始终明确当前位置。
- 首屏优先呈现当前状态、关键指标和下一步操作，次要信息采用渐进披露。
- 将手机上的记录表格替换为易扫描、易触控的纵向记录卡片，并提供完整详情。
- 让有效主操作在拇指可达区域出现，同时不制造无效、不可执行或误导性的支付入口。
- 保持桌面页面、现有业务逻辑、服务接口和路由契约不变，避免维护两套商业功能。

## 范围

本轮只覆盖以下个人商业设置页：

- `SettingsTabs.Plans`
- `SettingsTabs.Credits`
- `SettingsTabs.Billing`
- `SettingsTabs.Usage`
- `SettingsTabs.Referral`

涉及的共享移动呈现边界位于 `src/business/client/BusinessSettingPages/`，路由继续使用 `src/routes/(mobile)/settings/[tab]/index.tsx` 和 `SettingsContent`。

## 非目标

- 不开发原生 App、Expo 客户端或 PWA。
- 不启用在线支付，不修改支付宝、微信支付或订单结算开关。
- 不新增独立的 mobile subscription API；继续使用 `src/services/commercial.ts` 和现有 `lambdaClient` 路由。
- 不重构商业数据库、计费规则、会员权益或后台配置模型。
- 不重新设计全部手机设置页、聊天、发现或任务模块。
- 不改变桌面信息架构和桌面表格呈现。

## 已确认的产品决策

1. 使用共享移动体验组件层，不为五个页面复制独立业务页面。
2. 核心状态和操作优先，次要明细默认折叠。
3. 五页顶部提供可横向滚动并吸顶的快捷标签。
4. 手机记录使用纵向卡片，点击后通过底部抽屉查看完整字段。
5. 仅在存在可执行主操作时显示底部固定操作条。

## 设计原则

### 自然

- 页面顶部保持一个移动标题栏；快捷标签位于其下方，不再增加第二层页面标题。
- 触控区域最小高度为 `44px`，不依赖 hover 才能发现操作。
- 页面切换后滚动到内容顶部，当前标签自动滚入可视区域。

### 明确

- 首屏回答三个问题：当前状态是什么、重要数值是多少、下一步能做什么。
- 不可购买、未配置或接口失败必须说明原因及可执行的替代路径。
- 记录卡片只显示最有辨识度的字段，完整字段在详情抽屉中呈现。

### 确定

- 加载、空数据、错误和正常数据四种状态都必须有稳定布局。
- 底部操作条只显示真实可执行操作，不把“暂未接入”包装成按钮。
- 固定操作条不得遮挡内容、系统安全区或可滚动记录。

### 渐进

- 套餐对比、模型价格、统计图和规则等高信息密度区域默认折叠。
- 用户展开后仍在当前路由和滚动上下文内，不跳转到新的说明页。

## 共享组件架构

### `BusinessSettingsPageShell`

继续作为桌面和移动呈现的统一入口，并扩展以下能力：

- 根据 `mobile` 决定是否渲染桌面 `SettingHeader`。
- 在移动模式下组合快捷标签、页面内容和可选底部操作条。
- 根据是否存在底部操作条计算内容底部留白。
- 保持桌面默认 `subscriptionPageStyles.pageStack` 和现有自定义 `className` 行为。

### `BusinessMobileTabs`

- 固定顺序为：套餐、积分、账单、用量、推荐。
- 使用当前路由确定 active tab，不维护第二份选择状态。
- 通过 `useWorkspaceAwareNavigate` 导航，并使用 `{ escape: true }` 保持个人设置边界。
- 位于移动滚动容器顶部，使用 `position: sticky`；移动标题栏已在滚动容器外，因此 sticky 的 `top` 为容器顶部。
- 使用横向滚动的 `tablist`，当前项在初次进入和路由切换后自动 `scrollIntoView({ block: 'nearest', inline: 'nearest' })`。
- 标签高度至少 `44px`，活动态同时使用文字权重和指示线，不只依赖颜色。

### `BusinessMobileSection`

- 提供 `title`、可选 `summary`、`defaultOpen` 和内容区域。
- 核心区块默认展开；对比、历史、图表、FAQ 和规则默认折叠。
- 折叠控制整行可点击，使用明确的展开/收起图标和 `aria-expanded`。
- 区块是页面结构，不再在外层套装饰性卡片；内部单个实体可以使用卡片。

### `BusinessMobileRecordList`

- 输入现有记录数组、加载状态、空状态配置、摘要渲染器和详情渲染器。
- 每条记录显示主标识、状态、时间和一至两个关键数值；整行作为可点击目标。
- 点击记录后使用 `@lobehub/ui/base-ui` 的 `FloatingSheet` 展示完整字段。
- 抽屉关闭后将焦点恢复到触发记录，支持键盘和屏幕阅读器。
- 大列表继续沿用服务端 `limit`；本轮不新增无限滚动或分页协议。

### `BusinessMobileActionBar`

- 只接收一个 primary action 和可选的低优先级辅助信息。
- 使用视口底部固定层并适配 `env(safe-area-inset-bottom)`。
- 通过现有 Portal/overlay 层和设计 token 管理层级，不引入任意 z-index。
- 按钮占满可用宽度，最小高度 `44px`。
- 页面外壳按操作条实际高度预留底部空间，最后一条内容可以完整滚出操作条覆盖区域。

## 导航与状态流

```text
/settings/:tab
  -> MobileSettingsWrapper
  -> SettingsContent mobile
  -> Business settings page
  -> BusinessSettingsPageShell
     -> BusinessMobileTabs
     -> page sections
     -> optional BusinessMobileActionBar
```

快捷标签只改变路由；页面数据仍由各页面现有 SWR 请求和 `commercialService` 获取。组件不缓存商业数据，也不引入新的全局 store。路由切换后移动滚动容器回到顶部；SWR 继续负责去重和缓存，因此返回页面时可以复用已有数据。

## 页面信息架构

### 套餐 `Plans`

默认展开：

1. 当前套餐、计费周期和续费状态。
2. 可用计费周期选择。
3. 套餐横向卡片列表。

默认折叠：

- 套餐对比。
- 文本模型价格。
- 常见问题与支持入口。

套餐横滑区使用 `scroll-snap-type: x mandatory`，卡片宽度在手机上保持稳定，并露出下一张卡片的一部分。活动/当前套餐不能依靠 hover 表达。存在真实 purchase URL 时底部操作条显示升级操作；没有可购买周期时只提供可执行的兑换码入口，不显示无效购买按钮。

### 积分 `Credits`

默认展开：

1. 可用总余额和订阅、充值、推荐来源摘要。
2. 当前可执行的补充积分路径。
3. 积分包选择或兑换入口。

默认折叠：

- 充值记录。
- 积分使用明细。
- 自动充值说明。

在线支付关闭时，页面明确显示“暂未接入”说明，但不保留看似可支付的 primary 按钮。免费用户可执行的主操作为升级套餐；已具备资格但支付关闭时，可执行主操作为使用兑换码。

### 账单 `Billing`

默认展开：

1. 当前周期金额、状态、周期和续费/结束日期。
2. 待处理套餐变更提示。
3. 当前套餐摘要。

默认折叠：

- 套餐变更记录卡片列表。
- 兑换码入口。

账单页不模拟支付流水；现有套餐变更记录继续作为当前可用的历史来源。底部主操作为升级套餐，并导航到 `/settings/plans`。

### 用量 `Usage`

默认展开：

1. 紧凑筛选栏：月份和模型/服务商维度。
2. 本月核心指标。
3. 用量趋势摘要。

默认折叠：

- 复杂趋势图。
- 详细用量记录卡片。

筛选控件在 `360px` 下分为两行或全宽，不允许压缩成难以点击的窄控件。筛选变化继续触发现有查询，不增加客户端派生数据源。

### 推荐 `Referral`

默认展开：

1. 邀请总数、有效转化、累计奖励和可领取状态。
2. 推荐码与推荐链接，一键复制。
3. 注册三天内补填邀请码入口。

默认折叠：

- 推荐记录卡片列表。
- 完整计划规则。

存在可领取奖励时，底部操作条显示领取操作；否则不固定普通复制按钮。编辑推荐码时保留当前输入，失败后不清空草稿。

## 响应式与视觉规则

- 验收视口：`360x800`、`390x844`、`430x932`。
- 移动页面横向 padding 为 `16px`；标签条可以延伸到视口边缘，但标签内容保留触控留白。
- 页面级标题由移动 Header 提供；内容首屏使用 `20px` 至 `22px` 的语义标题，不使用桌面 `24px` 设置标题。
- 套餐卡片圆角不超过现有设计系统的 `8px`，卡片之间 gap 为 `12px`。
- 固定格式区域使用明确宽度、`min-width: 0`、grid 轨道或 `aspect-ratio`，动态文本不能推动整体页面宽度。
- 只允许套餐横滑区、标签条和确有必要的内容容器内部横向滚动；`body` 和移动主滚动容器不得横向溢出。
- 禁止嵌套装饰性卡片、悬浮装饰和仅靠颜色表达状态。

## 加载、空状态和错误处理

### 加载

- 首次加载使用与最终结构同尺寸的 Skeleton，避免标签下方大幅跳动。
- 记录列表加载时展示 3 条记录骨架，而不是空白表格。
- 不使用 antd `Spin`。

### 空状态

- 套餐为空：说明后台尚未配置价格，并提供兑换码或联系管理员的真实路径。
- 积分记录为空：说明尚无积分变动，并指向可用的积分来源。
- 账单记录为空：说明尚无套餐变更，不暗示支付记录缺失。
- 用量为空：说明当前月份暂无用量，并允许切换月份。
- 推荐记录为空：说明分享推荐链接后记录会出现在此处，并提供复制入口。

### 错误

- SWR 请求错误在对应区块内显示原因概述和“重试”操作。
- 已成功加载的其他区块不因单个请求失败而消失。
- 错误状态不自动跳转，也不清除用户正在编辑的推荐码或筛选条件。

## 可访问性与文案

- tablist、折叠区、记录按钮和详情抽屉使用正确的 ARIA 状态。
- 所有 icon-only 控件必须提供可访问名称和 tooltip。
- 状态标签同时包含文字，不只显示颜色或图标。
- 新增用户文案进入现有 i18n namespace；英文源和中文翻译在同一变更中维护。
- 数字、货币、日期和积分继续使用现有格式化函数，不在移动组件内重复格式逻辑。

## 测试策略

### 单元与组件测试

- `BusinessMobileTabs`：活动态、personal-only 导航、自动滚入可视区域。
- `BusinessMobileSection`：默认展开、折叠切换、ARIA 状态。
- `BusinessMobileRecordList`：loading、empty、records、详情抽屉和焦点恢复。
- `BusinessMobileActionBar`：有操作/无操作、安全区 class 和内容留白契约。
- 五个页面：移动组件分支和桌面原组件分支均存在，商业请求与事件处理不复制。

### 浏览器验证

Browser plugin 当前不可用时，使用仓库已有 Playwright 依赖进行验证。覆盖：

1. `/settings/plans`：标签切换、套餐横滑、折叠区、兑换入口。
2. `/settings/credits`：余额首屏、积分来源、记录卡片和详情抽屉。
3. `/settings/billing`：摘要、待处理提示、升级导航和记录详情。
4. `/settings/usage`：月份/维度筛选、图表折叠和窄屏控件布局。
5. `/settings/referral`：复制、编辑、奖励操作、记录详情和规则折叠。

每个移动视口检查页面身份、非空渲染、框架错误覆盖层、控制台错误、页面横向溢出、元素重叠、触控尺寸和安全区。另以 `1280px` 验证桌面标题、表格和页面布局没有回归。

## 验收标准

1. 五个页面在 `360px`、`390px`、`430px` 宽度下无页面级横向溢出或控件重叠。
2. 顶部只存在一个页面标题；快捷标签吸顶且活动项始终可见。
3. 五个标签可以直接切换，并始终保持个人设置路由，不进入活动工作区路径。
4. 核心状态与下一步操作在首屏或一次自然滚动内可见；次要明细默认折叠。
5. 手机记录不渲染桌面表格，记录卡片可以打开完整详情抽屉。
6. 底部操作条只在真实可执行操作存在时出现，适配安全区且不遮挡最后一条内容。
7. 加载、空数据、错误和正常数据状态都有明确呈现及可执行下一步。
8. 套餐卡片可以稳定横滑和 snap，页面本身保持 `scrollWidth === viewportWidth`。
9. `1280px` 桌面布局继续显示原有 `SettingHeader`、表格和操作结构。
10. 不新增移动 API、不启用支付、不修改商业数据契约、数据库或生产功能开关。
11. 聚焦 Vitest、`tsgo --noEmit`、目标 ESLint、Prettier、`git diff --check` 和 Playwright 移动/桌面验证通过；无法执行的门槛必须记录准确阻塞原因。

## 风险与控制

- **共享页面分支过多**：移动差异限制在共享呈现组件和小型页面适配器，不复制数据请求和 mutation。
- **固定操作条遮挡内容**：由外壳统一测算和预留底部空间，并在三个移动视口验证最后一项可见。
- **折叠导致信息难发现**：核心状态默认展开，折叠标题包含摘要或记录数量。
- **卡片替代表格遗漏字段**：摘要字段和详情字段分别建立显式映射，并通过组件测试覆盖。
- **本地后端不可用导致验证不足**：浏览器测试使用可控 fixture/mock 覆盖正常、空和错误状态；生产联调仍作为独立部署验证，不在本轮静默假定通过。

## 交付边界

本设计完成后，实施应按共享基础组件、页面逐步接入、浏览器回归三个阶段推进。每个阶段保持可测试和可回滚。最终交付为源码、聚焦测试和验证证据；临时截图、服务日志和本地调试文件不得提交到仓库。
